# 🤖 多Agent协作指南

> 基于Deep Research重构项目的成功实践，总结出的可复用协作模式

## 📋 Part 1: 核心Agent协作方法论

### 🎯 协作模式概述

**多Agent并行协作模式**：将大型重构任务分解为独立工作包，分配给不同AI并行执行，由核心Agent统一规划、审查和集成。

**核心优势**：
- ⚡ **并行加速**：4个AI同时工作，效率提升300%
- 🎯 **专注分工**：每个AI专注单一模块，质量更高
- 🔍 **质量把控**：核心Agent审查机制，确保一致性
- 🔄 **灵活调整**：任务失败可快速重新分配

### 🏗️ 核心Agent职责与流程

#### 1️⃣ **任务分析阶段**
```
📊 代码库理解 → 🎯 问题识别 → 📐 架构设计 → 📦 任务分解
```

**关键动作**：
- 深度分析现有代码结构和问题
- 设计目标架构和模块划分
- 识别模块间依赖关系
- 制定分解策略（优先独立模块，后处理依赖）

#### 2️⃣ **工作包规划阶段**
```
📋 任务定义 → 🔗 依赖分析 → ⏱️ 优先级排序 → 📝 文档准备
```

**工作包模板**：
- **任务概述**：清晰描述要做什么
- **具体目标**：要创建/修改的文件
- **参考代码**：必须查看的原始代码位置（具体行号）
- **验收标准**：如何判断任务完成
- **约束条件**：不能修改的文件
- **依赖关系**：需要等待的其他工作包

#### 3️⃣ **任务分配阶段**
```
🎯 AI分配 → 📤 提示词生成 → ⏰ 执行监控 → 📝 进度追踪
```

**提示词原则**：
- **简洁明确**：3-5句话说清楚任务
- **指向具体**：明确文档路径和代码行号
- **包含验证**：告诉AI如何自我验证
- **避免歧义**：使用精确的技术术语

#### 4️⃣ **质量审查阶段**
```
🔍 文件验证 → 📖 代码审查 → ✅ 标准检查 → 📋 结果记录
```

**审查检查清单**：
- [ ] 文件是否真实存在（防止虚假报告）
- [ ] 代码逻辑是否完整（无占位符）
- [ ] 是否符合验收标准
- [ ] 是否遵守约束条件
- [ ] TypeScript是否编译通过

#### 5️⃣ **调试集成阶段**
```
🔧 问题识别 → 📋 修复计划 → 🎯 任务分配 → ✅ 最终验证
```

### 🚨 常见问题与解决方案

| 问题类型 | 症状 | 解决方案 |
|---------|------|---------|
| **虚假报告** | AI声称完成但文件不存在 | 强制文件验证，重新分配可靠AI |
| **依赖冲突** | 模块间接口不匹配 | 先完成接口定义，再分配实现任务 |
| **代码重复** | 多个AI实现相似逻辑 | 明确模块边界，避免职责重叠 |
| **质量不一致** | 不同模块代码风格差异 | 统一编码规范，提供参考示例 |

### 💡 最佳实践

1. **依赖优先原则**：先分配无依赖的模块（如WP1），再分配有依赖的模块
2. **验证驱动原则**：每个任务都要有明确的验证方法
3. **文档先行原则**：先创建工作包文档，再分配任务
4. **迭代改进原则**：根据反馈及时调整提示词和工作包定义

## 🎯 快速开始指南

### 对于核心Agent：
1. 分析现有代码，识别重构目标
2. 使用工作包模板创建详细任务文档
3. 生成简洁提示词分配给专门AI
4. 使用审查清单验证每个完成的任务
5. 收集问题，创建修复任务进行迭代

### 对于执行AI：
1. 仔细阅读工作包文档
2. 按照验收标准完成任务
3. 在工作包文档中更新完成情况
4. 提供详细的实现反馈

### 对于项目管理者：
1. 定期查看进度追踪文档
2. 根据进度调整资源分配
3. 识别瓶颈并及时干预
4. 总结经验完善协作流程
